# Security and privacy

- The ESP32 API and dashboard use unencrypted HTTP. Keep them on trusted networks.
- The dashboard binds to `127.0.0.1` by default. Do not expose its port to a LAN or the internet without suitable transport security and access controls.
- Authenticated API routes require the configured Orb token; `/health` and static dashboard/media files are public.
- The observer forwards aggregate mood, source, session and instance identifiers, ordering metadata, bounded labels (including session titles), tool names and usage counters. Pending permissions add an allowlisted kind, intention (≤80 UTF-8 bytes), short preview (≤60 UTF-8 bytes), and a random nonce. **Actionable permissions send the exact complete multiline shell command or complete supported non-shell structured JSON request in `attention.command`, up to 1,024 UTF-8 bytes, to every authenticated configured destination.** This includes full paths, URLs (potentially credentials/query strings), tool arguments, and any diffs or contents in the permission request. These details, intentions, previews and titles may contain secrets. This is not metadata-only telemetry and does not guarantee secret redaction. Conversation prompts, reasoning, question/plan/limit details, user answers and tool results are not independently forwarded. See [observer behavior and privacy](../observer/README.md#behavior-and-privacy).
- Decisions require a live actionable permission and SDK pending-list/resolver capability. The first yellow-segment tap opens the command/request card on both dashboard and firmware. **Approve** submits immediately from that card; there is no separate review screen or checkbox. The Orb shows a compact command preview and indicates when longer text continues. Denial is direct. Missing, oversized (>1,024 UTF-8 bytes) or unsafe details remain computer-only (tabs and line breaks are allowed); truncated summaries never authorize a decision. Supported non-shell kinds are read/write, URL, MCP, memory and custom-tool; other/unknown kinds, questions, plan reviews and session limits are computer-only.
- Authenticated observer event replies carry only the attention nonce and `approve`/`deny`; **SDK permission request IDs never leave the host**. One-second actionable heartbeats must remain fresh (dashboard: 10 seconds; firmware: 30 seconds). Queued decisions expire after 30 seconds and are bound to the session, observer owner and exact attention content. Changed authoritative request details rotate the nonce and require fresh review; the observer rechecks the live SDK request before applying `approve-once` or `reject`. Conflicting choices across destinations permanently block remote resolution for that nonce, even after a choice expires; computer resolution is required. There is no session-wide or persistent blanket grant. Protect destination tokens as access to sensitive review data and permission controls, not merely status telemetry. Current real-SDK tests pass, but do not prove live user VS Code/CLI dialog closure. USB hardware was absent; no flash or physical touch verification occurred.
- Physical-device state and settings remain on the ESP32. Dashboard state is held in the service process; GitHub deduplication data and a UI-saved dashboard PAT are stored in the Compose volume.
- A dashboard GitHub PAT may be supplied through `.env`/Compose or saved from the local UI. UI-managed credentials are stored privately and are never returned to the browser or diagnostics. Authenticated state includes alert titles, repository names, and links, so protect the dashboard observer token (`observer-token.json` in the dashboard data volume, mirrored in the Copilot Orb configuration) and the ESP32 token. Never expose credentials through public diagnostics.

For service configuration and supported deployment options, see [Orb Dashboard](dashboard.md). For device credential provisioning, see [getting started](getting-started.md).
